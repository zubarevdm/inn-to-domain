# inn2domain

Пайплайн определяет домен официального сайта российской организации по ИНН.

```bash
$ inn2domain 7721581040
{"domain": "dadata.ru"}

$ inn2domain 7805590027
{"domain": null}
```

Второй пример важнее первого. ООО «ПЛАСТ» из Петербурга не имеет сайта, при этом
домен `plast.ru` существует и принадлежит другой компании. Пайплайн отвечает
null, потому что неверный домен в справочнике дороже пустого поля.

Решение задания 1 лежит в [docs/task1.md](docs/task1.md).

## Установка

```bash
pip install -e .
cp .env.example .env   # и заполнить ключи
```

Нужны три ключа: DaData (карточка организации по ИНН), GigaChat (LLM) и
Yandex Search API либо Exa (веб-поиск). Все три имеют бесплатный или пробный
режим.

## Запуск

```bash
inn2domain 7707083893                  # ответ в формате задания
inn2domain 7707083893 --verbose        # ход работы
inn2domain 7707083893 --trace          # кандидаты, доказательства, решение LLM
inn2domain 7707083893 --mode verify    # без LLM, только реквизиты

uvicorn inn2domain.api:app --port 8000
curl -X POST localhost:8000/resolve -H "Content-Type: application/json" \
     -d '{"inn": "7721581040"}'
```

## Как устроено

```
ИНН
 │
 ├─ 1. Валидация по контрольной сумме        мусор не доходит до платных API
 ├─ 2. Карточка организации (DaData)         название, ОГРН, город, статус
 ├─ 3. Поиск, 5 запросов                     по ИНН, по бренду, по бренду с городом
 ├─ 4. Сборка кандидатов                     нормализация доменов, агрегаторы, сниппеты
 ├─ 5. Проверка кандидатов                   главная + контакты + реквизиты, WHOIS
 ├─ 6. Решение LLM (GigaChat)                выбор из списка кандидатов, строгий JSON
 └─ 7. Политика ответа                       нет доказательств → null
```

### 2. Зачем карточка организации

По одному ИНН поисковик выдаёт агрегаторы реквизитов, самого сайта в выдаче нет.
Искать нужно по названию, бренду и городу, а проверять найденное по ИНН и ОГРН.
Карточка из ЕГРЮЛ даёт и то, и другое.

### 3. Пять запросов вместо одного

Каждый запрос слеп по-своему. Поиск по ИНН выводит агрегаторы, зато их сниппеты
часто содержат адрес сайта. Поиск по названию юрлица бесполезен, когда бренд с
ним не совпадает: ООО «Интернет Решения» это ozon.ru, ООО «Дейта Кью» это
dadata.ru. Поиск по названию с городом помогает малому бизнесу с типовым именем.

### 4. Кандидаты

Домены нормализуются: убирается www, punycode раскрывается в юникод,
поддомены схлопываются до значимого имени. Исключение для конструкторов сайтов:
`my-shop.tilda.ws` остаётся целиком, потому что там поддомен и есть сайт компании.

Агрегаторы реквизитов, соцсети и маркетплейсы не выбрасываются целиком, как это
делает обычный блок-лист. Каждый такой портал сам является чьим-то сайтом:
ozon.ru принадлежит ООО «Интернет Решения». Правило мягче: портал проходит
дальше, только если на его главной или в контактах опубликованы реквизиты
запрошенной организации, либо домен совпадает с её брендом. Чужие ИНН площадки
публикуют на глубоких страницах, куда пайплайн не заходит, поэтому ложных
срабатываний это не добавляет.

Отдельный источник кандидатов — домены, написанные словами в тексте выдачи
(«Сайт: ozon.ru» в карточке агрегатора). Вернуть агрегатор как ответ нельзя, а
вот использовать его подсказку и проверить её самостоятельно можно.

### 5. Проверка: главный этап

Для каждого кандидата загружается главная страница, ссылки на контакты и
реквизиты из разметки, плюс типовые адреса `/contacts`, `/about`, `/rekvizity`,
`/privacy` напрямую. В тексте ищется ИНН и ОГРН организации, причём цифры могут
быть разделены пробелами.

Две ловушки, из-за которых наивный поиск подстроки врёт:

1. В подвале сайта стоит ИНН веб-студии: «разработка сайта, ООО ...». Вокруг
   найденного номера проверяется контекст, такое совпадение помечается.
2. Бухгалтерские фирмы и агрегаторы публикуют чужие реквизиты. Отсюда правило
   для порталов выше.

Дополнительно опрашивается WHOIS. Реестр .ru отдаёт поля `org` и `taxpayer-id`,
то есть название и ИНН владельца домена, но сейчас они скрыты у всех проверенных
доменов. Остаётся дата регистрации, полезная для контроля перехвата
освободившихся доменов. Код к появлению этих данных готов.

### 6. LLM

GigaChat получает карточку организации и список кандидатов с доказательствами и
возвращает строгий JSON. Два правила снимают известные риски:

- модель выбирает домен **из списка кандидатов**. Ответ вне списка отбрасывается
  кодом, поэтому галлюцинация не может стать результатом;
- всё, что пришло из интернета, подаётся в отдельном блоке с пометкой
  «недоверенные данные». На сайте может быть текст, адресованный модели.

Если уверенности нет, модель возвращает поисковый запрос, пайплайн выполняет его
и спрашивает ещё раз. Не больше двух кругов.

### 7. Политика ответа

Порядок решающих правил:

1. Реквизиты организации найдены на сайте → это ответ, уверенность 0.9–0.97.
2. Реквизиты найдены на одном домене, LLM предлагает другой → верю реквизитам,
   уверенность снижаю.
3. Реквизитов нет, LLM уверена ≥ 0.6 → нужен независимый признак: адрес сайта из
   карточки организации, домен корпоративной почты либо совпадение бренда с
   доменом вместе с городом на странице. Одного совпадения названия мало:
   у ООО «ПЛАСТ» из Петербурга и у сайта plast.ru из Москвы название совпадает
   полностью, а компании разные.
4. Иначе null.

## Оценка качества

Набор из 35 организаций: 23 с сайтом, 12 без. Метки ставились вручную, ответы
пайплайна в разметке не участвовали.

| метрика | только поиск | поиск + проверка реквизитов | полный пайплайн |
|---|---|---|---|
| выдано доменов | 34 | 4 | 15 |
| точность | 0.38 | 0.0 | **0.93** |
| полнота | 0.57 | 0.0 | 0.61 |
| верных null | 0.0 | 1.0 | 0.92 |
| неверных доменов | 9 | 4 | **0** |

Как собран набор и что означают метрики — в [eval/README.md](eval/README.md),
разбор ошибок и план улучшений — в [eval/report.md](eval/report.md).

## Ограничения

- Крупные площадки закрыты от ботов: ozon.ru отвечает 403. Часть сайтов отдаёт
  пустой HTML и рисует содержимое на JavaScript, как yandex.ru. Реквизитов в
  таком ответе нет.
- Разметка собрана вручную по доказательствам и смещена в сторону компаний,
  которые вообще находятся поиском.
- Пайплайн отвечает по одному ИНН. Для массовой обработки нужны очередь,
  параллелизм и соблюдение лимитов провайдеров.
- Лицензии поисковых API ограничивают хранение выдачи. Для коммерческого
  использования условия нужно читать отдельно.

## Структура

```
src/inn2domain/
  pipeline.py      оркестратор и политика ответа
  card.py          карточка организации (DaData)
  search/          провайдеры поиска: Yandex Search API, Exa
  fetch.py         загрузка страниц, HTML в текст, поиск страниц с реквизитами
  extract.py       поиск ИНН и ОГРН в тексте, сравнение названий, транслитерация
  domains.py       нормализация доменов, список порталов и агрегаторов
  whois.py         владелец и дата регистрации домена
  llm/             клиент GigaChat и промпты
  inn.py           контрольные суммы ИНН и ОГРН
  cache.py         SQLite-кэш поиска, страниц и ответов LLM
  cli.py, api.py   CLI и HTTP
eval/              выборка, разметка, прогон метрик, отчёт
docs/task1.md      ответ на задание 1
tests/             юнит-тесты
```
